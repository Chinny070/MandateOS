# MandateOS dashboard

React, TypeScript and Vite dashboard using the stable GenLayerJS `studionet` client (chain ID 61999). It reads only latest-final contract state. The only write currently implemented is a user-signed governance vote; the app never stores keys or submits transactions without an explicit wallet action.

## Start

```powershell
npm ci
npm run dev
```

Optional `.env.local` values:

```text
VITE_MANDATE_OS_ADDRESS=0x...
VITE_PROJECT_VAULT_ADDRESS=0x...
VITE_PROJECT_ID=...
```

The repository has no deployed MandateOS or ProjectVault addresses. Leave the configuration empty until real addresses are provided; empty states mean unavailable and are not seeded with test values. Contract views currently do not enumerate project or proposal IDs, so enter known identifiers in the dashboard to inspect those records. Browser storage contains query handles only, not authoritative financial data.

The EOA payment panel intentionally remains `UNVERIFIED`: the SDK's `getTriggeredTransactionIds` implementation scans `InternalMessageProcessed` events and exposes IC child links, not the EVM execution record for external EOA value messages. A matching balance delta or finalized parent intent is not presented as settlement proof.

Keeper reports are generated by `python -m keeper.cli`. Imported JSON is labeled unsigned local evidence and is never promoted to contract settlement state.

## Verification

```powershell
npm run typecheck
npm test
npm run build
```

Configuration values and every displayed financial field come from StudioNet contract/RPC reads or are shown as unavailable. No sample projects, balances, profits, transaction hashes, or validator decisions are bundled.
